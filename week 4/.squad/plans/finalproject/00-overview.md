# finalproject — plan overview

Entry point for the **finalproject** feature. Stories execute in order by their `NN` prefix.

Covers Azure DevOps work item **28 — US14 Final System Review, Simplification, UI/UX Polish & Stability**. The work item's eleven task groups are split across five stories, ordered so that each one has a verifiable baseline to regress against. **This feature adds no feature, no route, no permission, no migration, and no dependency.** Every task is a repair, a deletion, a consolidation, or a verification.

## Dependency notes

- **Story 24 exists because the Definition of Done is currently false.** `npm run build` in `backend-nodejs/` fails with **52 TypeScript errors**; `npm run type-check` in `frontend-vuejs/` fails with **19**; **3 of 205** frontend tests fail; ESLint reports **217** errors. Nothing downstream can claim "no regression" until those numbers are zero. **Do not reorder this story.**
- **`req.id` does not exist and never did.** Fourteen sites in the customers module read it; the augmentation in `express.d.ts` declares `correlationId`, which the other 67 sites use. Because `JSON.stringify` drops an `undefined` value, every `/api/v1/customers/*` success response has silently been missing its `correlationId` — no test caught it, and no typecheck could, because the surrounding controller was implicitly `any`. **Fixing the controller typing is what exposes the runtime bug**, which is why the two are one story.
- **Thirteen CSS custom properties are used by 25 files and defined by none — 68 declarations in total.** An undefined `var()` is *invalid at computed-value time*, so the browser discards the whole declaration. `BaseInput.vue:70` is `border: 1px solid var(--color-gray-300)`, so **no input in the application has a border**; `BaseButton.vue:74` is `background-color: var(--color-primary-dark)` on hover, so **the primary button loses its fill when hovered**. Story 26's task 1 is thirteen lines of CSS and is the single highest-value edit in the feature. Its regression guard is a test that diffs used tokens against defined ones.
- **`src/assets/base.css` is the Vue scaffold theme and it defines a dark mode nobody asked for.** Lines 39–51 flip `--color-background`, `--color-text`, `--color-border`, and `--color-heading` under `prefers-color-scheme: dark`, while every `BaseCard` keeps a hardcoded white. **The demo machine's OS setting decides whether the app looks broken.** Story 26 deletes the file — after replacing every token it uniquely defines, not before.
- **`--color-primary: #3b82f6` fails WCAG AA.** With white text it is **3.68:1**, below the 4.5:1 threshold, and it is the colour of every primary button, every link, and the active sidebar item. Story 26 moves it to `#2563eb` (**5.11:1**). `--color-primary-rgb` must be updated in the same edit — CSS cannot derive channels from a hex custom property, and a mismatch produces a focus ring in the old blue that nobody notices.
- **There is not one `:focus-visible` rule and not one `keydown` handler in the entire frontend.** Keyboard focus is invisible everywhere (Story 26), and no dialog closes with Escape, traps focus, or restores it on close (Story 27). Every create, edit, and confirm flow in the application is a `BaseDialog`, so both fixes land in one component each and propagate.
- **Story 26 must run before Story 27's focus trap.** A trap without a visible ring is worse than neither — the user is held somewhere they cannot see.
- **Twelve files are deleted in Story 25 and every one is verified unreachable.** Nine Vite scaffold components, `stores/counter.ts`, `src/assets/styles/main.css` (imported by nothing; `src/assets/main.css` is the live one — two files, same basename), and `backend-nodejs/src/modules/customers/attachments.upload.ts`, a 65-line copy of the shared uploader that **no file imports**. `handleUpload` and `customerDir` in the shared module are documented as "kept for backward compatibility with existing imports"; **there are no such imports** — only the module's own spec.
- **i18n keys are never swept mechanically.** A literal-reference scan reports 91 unreferenced keys, but many are built by interpolation — `audit.action.${row.action}`, `tickets.status.${code}`, `portal.priority.${code}`, `customers.history.kind.${kind}`. Deleting one shows the raw key on screen and no test catches it. **Grep the parent prefix before removing anything**, and remove from `en.json` and `ar.json` together or not at all; `locale-parity.spec.ts` enforces the pairing and the no-empty-Arabic rule.
- **The `customers.attachments.*` and `customers.history.*` keys look dead and are not junk.** Those 23 keys, fully translated in both files, belong to **four live backend endpoints, a service, and an integration test with no screen** — the one genuine module-integration gap in the product. Story 28 wires them into the customer detail page, in the position Story 27 clears by deleting the `Story 10: Placeholder` card that renders as a blank white box on every customer today. **Story 25 must not delete these keys.**
- **`AttachmentsList` gets one `i18nPrefix` prop, not a second copy.** `tickets.attachments.*` and `customers.attachments.*` have identical key sets. A prefix prop is a smaller change than a parallel component and is the only new prop this feature introduces anywhere.
- **Three RTL defects make the Arabic layout wrong, not merely mirrored.** `AppSidebar.vue:177` hides the mobile drawer with `transform: translateX(-100%)` while docking it with `inset-inline-start: 0` — in Arabic that moves it *into* view, so **the drawer does not close**. `BaseDialog.vue:150–156` applies `flex-direction: row-reverse` to a header that is already reversed by the document direction, putting the close button on the wrong side, and pairs it with a physical `margin-right`. Both are only visible in Arabic, and the sidebar one only below 768 px.
- **Two hardcoded English strings survive on accessibility affordances.** `AppTopbar.vue:62` is `computed(() => 'Toggle menu')` — the accessible name of the only control that opens navigation on mobile — and `BaseDialog.vue:14` is `aria-label="Close dialog"`. Both are invisible to a sighted English reviewer and wrong for every Arabic user.
- **`JWT_SECRET` has a default (`env.ts:17`), in a schema that otherwise fails closed.** A production deployment that forgets the variable boots and signs tokens with a value committed to the repository. Story 28 keeps the developer convenience and refuses to start in production. The `.env` file itself is correctly ignored by `backend-nodejs/.gitignore:3` — that part is fine.
- **The rate limit is a demo hazard, not a security win.** `app.ts:38–42` allows **100 requests per 15 minutes per IP across all of `/api`**, and the Vite dev proxy makes every client one IP. Story 28 raises the general limit and adds a tight limiter on `/api/v1/auth/login`, which is the endpoint where throttling is actually protective. The login limiter must be registered **before** `app.use('/api/v1', v1)` or it never runs.
- **A `CUSTOMER` holds `tickets.read`, and today only a router redirect stands between them and other customers' tickets.** `router/index.ts:161–168` records this as a deliberate frontend-only mitigation left over from Story 22. Story 28 closes it **on the server** with a role check on `req.auth.roleCode` — no new permission code, because that would change `permissions.constants.ts` and force a re-seed, which this feature's scope excludes.
- **The integration suite is not part of the per-story gate and is run once, in Story 28.** Seven `.itest.ts` files need a live SQL Server; `vitest.config.ts` runs them as a separate `integration` project with `fileParallelism: false`. Stories 24, 25, and 28 each change endpoints those tests cover — the `correlationId` field, the 404→422 change on attachment upload, the history paging schema, the rate limits — so **expect failures and classify each one** as a regression, a pre-existing problem now visible, or a stale test.
- **Every story ends with the same gate and it is not negotiable:** both projects build, every unit test passes, lint is clean, and no pre-existing test was edited to make it pass. The one documented exception is `attachments.upload.spec.ts` in Story 25, whose subject is deleted — and even there, the path-traversal assertion must survive on `ownerDir` rather than being lost with the block around it.
